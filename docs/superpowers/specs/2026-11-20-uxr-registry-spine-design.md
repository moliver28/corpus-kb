# UXR Registry-Spine Design — corpus-rag plugin reinforcement

Date: 2026-11-20. Status: design approved by owner 2026-11-20 (scope addition: dual-backend parity, no plugin bloat). Adversarial completeness review (momus) applied 2026-11-20: 13 findings amended, all four blocking items resolved. Owner spec approval pending.

## 1. Goal

Novice UX researchers use the corpus-rag plugin. They must get the engine's NLP methods applied to their tasks without naming methods themselves. Today the plugin's UXR layer applies zero engine NLP. Classify is rule-based (`uxr_classify.py`). Quote check is difflib (`uxr_quotes.py:8-11`). The plugin reaches 1 of 12 engine method commands (`analysis-select-method`), named in prose and never invoked. The `analysis-route` router is wired nowhere. Codify ops are wired but never feed the UXR themes/rollup.

Success looks like this: a novice on either storage backend asks a plain-language UXR question. No config beyond normal setup is needed. The plugin routes the question, runs registry methods through one path, and explains results in plain English. Owner ruled out invocation-term-only fixes.

## 3. Locked decisions

- **D1 — Registry spine.** Plugin is a registry client, not a second brain. One invocation path: `corpus-rag op <name>` through op_runner. No plugin-local reimplementation of engine methods (zero-drift rule 1).
- **D2 — W1 is plugin-only.** Skills prose + one hook lane change. Zero engine diff in W1.
- **D3 — Hooks stay plain text** on stdout, existing mark scheme (once-per-study-per-day, declined respected), fail-open. Nudge text derives from `analysis-route` output (ranked + run_hint). The analyze lane today only NAMES the CLI in static text (`hook_events.py:76`). Deriving text from the router means a NEW shell-out to `corpus-kb analysis-route`. That call must be mark-gated FIRST. Marks are checked before the CLI runs, so the cost only lands on nudge-eligible prompts. It must be time-bounded (bounded timeout, default 10 s) and fail-open. On any failure, the lane falls back to today's static text. This shell-out is an explicit, documented exception to D1's one-invocation-path rule. Prompt hooks run with no study server and no `op_client` access. So the router is reached via one bounded `corpus-kb analysis-route` call (exact command form pinned in the plan). The nudge text template stays plugin-owned (successor to `LANE_TEXT`); the engine supplies data, the plugin owns the words. No envelope key additions in W1-W2.
- **D4 — New engine methods in W3**, registry-first: register rows (both mirrors) updated FIRST, then handler, then surfaces, then `poe gen`. Verified touch list per new method: register row plus packaged mirror. Then: **id-range validator `analysis/method_register.py:111-117` (`1 <= int(value) <= 30`; widen or make data-driven)**, loader EXPECTED_IDS ledger `method_register_loader.py:20,56-64`, **exactly-30 test pins `tests/test_method_register.py:160-163,194`**. Then: typed errors and exit codes per the error taxonomy (zero-drift rule 4). Then: auto-approve classification in `surface_registry.py` (`SERVER_AUTO_APPROVE`/`AUTO_APPROVE_WRITE_TOOLS`, locked by `tests/test_auto_approve_lockstep.py`). Then: handler in `tools/`, CLI wrapper in `cli/cli_analysis_methods.py`, HTTP route in `api/routes_analysis_methods.py` plus route table `api/http.py:231`. Then: socket `_Spec` arm in `api/_socket_rows.py`, catalogue row in `contracts/catalogue_analysis.py`, `surface_registry.py` (op row, help, skill entry, lockstep set). Then: parity rows in `tests/test_surface_parity_deep.py`. Then: telemetry `METHOD_FOR_OP` plus `_setup/doctor_journey_maps.py`. Then: persona-meter baseline re-record (new methods enter the walk automatically via their `question_phrases`). Then: `poe gen` artifacts (incl. ANALYSIS-METHODS.md, harness pack, ui manifest). MCP surface auto-generates.
- **D5 — Dual-backend parity, zero extra config.** Every plugin-reached engine path must work on `database.backend: postgres` AND `duckdb`. No user action is allowed. Covered paths: method ops, coding ops, search/ask/ingest, `/api/stats`, and the legacy `/api/query/sql` route (`uxr_commands.py:58-62`; dialect must be checked). The `wired_store` embedder gap was already closed on master (#521); no engine blocker remains. Tests follow the DuckDB-twin pattern landed by PR #525.
- **D6 — No plugin bloat.** Plugin additions are SKILL.md prose and thin command modules only. Zero new plugin dependencies (stdlib only), no engine config parsing in the plugin, no duplicated engine logic. The repo size ratchet scans only `src/scripts/tests` (`scripts/size_ratchet.py:37`). The plugin is outside it, so discipline is explicit and manual. New plugin code goes into new small modules — never grown into `codify_commands.py` (already 321 lines). The W4 review checks plugin file sizes. The plugin's own per-study SQLite store stays.
- **D7 — Data merges.** (a) `coding_export` rows (exported at `codify_commands.py:277`) append as a coded-evidence section to themes.md between the markers written by `uxr_summaries.py:32-41`. They also append to the rollup's evidence section (`uxr_rollup.py:91,140`), ordered after the model-written narrative. Owning commands are the existing uxr handlers that call those modules (`UXR_HANDLERS`, `uxr_analysis.py:129-144`). (b) Quote near-miss gets an advisory second opinion from `search_similar`; difflib stays the contract gate. (c) Files that fail classification get nearest-corpus-document suggestions via `search_similar` instead of a dead end. (d) When no external report tool is configured, the Contract-parity step runs the rollup as the default evidence source. It adds an honest degraded note instead of exit 1.
- **D8 — Families covered.** Qual coding + themes (W1-W2), sentiment + emotion (W1 wiring, W3 emotion method), survey analysis (W3), usability metrics (W3-W4). If the W3 entry check defeats `survey-openend-codes` (storage shape), the program stops. It re-scopes the survey family with the owner — no silent descope.

## 4. Waves

- **W1 — Plugin wiring (no engine change except the D5 blocker fix).** corpus-analyze: route-then-run (op analysis-route → ranked + run_hint → confirmed op through op_runner). corpus-research op table gains the 12 method rows. corpus-uxr gains method-chain steps (keyphrases-extract, clusters-inspect, sentiment-screen, contradictions-screen) with plain-English rationale. Analyze-lane hook calls analysis-route and prints the top method with its run command.
  Done-when: route-then-run proven by plugin unit tests (mocked runner, existing `plugin-tests` pattern). The analyze-lane hook renders route-derived text with mark-gate-first, a 10 s timeout, and static-text fallback (unit tests). Engine diff: none. Live both-backend execution proof is W4's walk-through.
- **W2 — Register-driven nudges + merges.** Route-derived nudge text; coding_export merge; quote near-miss assist; unmatched-class assist; degraded contract default.
  Done-when: nudge text names the route's top method. Merges are exercised by plugin tests. The corpus-uxr Contract step (`skills/corpus-uxr/SKILL.md:79`) exits 0 with a degraded note when no report tool exists.
- **W3 — Engine methods.** Candidates: `survey-openend-codes` (cluster, label, count open-end answers per question), `usability-severity` (rubric-score findings 0-4), `emotion-tag` (fixed-taxonomy NLI tagging). Entry check first: verify what the survey ingestion strategy stores per response. Full D4 checklist + plugin wiring + persona-meter baseline re-record in the same PR + DuckDB twin tests per handler.
  Done-when: `poe gen --check` clean, parity suites green, persona-meter within ceiling, both backends pass the new tests.
- **W4 — Hardening.** Whole-branch momus review; docs (ANALYSIS-METHODS regen, plugin README); novice walk-through validated live; backend-parity sweep report over every plugin-reached op.
  Done-when: review findings closed or filed. The walk-through reproduces the success criterion on Postgres and DuckDB. A manual plain-language pass covers all new plugin strings (hook text, SKILL prose, degraded notes). The `pytest -m ste` gate does not scan `plugins/`. A plugin file-size check runs.

## 5. Testing and gates

No new gate types. Extend `poe plugin-tests` (stdlib suite) for hook text derivation (marks, timeout, fallback text). The op-table-vs-live-inventory consistency check moves engine-side. A `tests/` gate parses the plugin SKILL.md op table against the contract catalogue. The plugin-tests CI leg installs no engine, so it cannot reach a live inventory there. Engine changes ride existing gates: parity suites, `poe gen --check`, warning ratchet, persona-meter, size ceilings. Suite defaults to skip-Ollama degraded mode; embedding-dependent steps degrade honestly.
